## 1. 프로젝트 개요

### 1.1 한 줄 요약

CSV 형식의 공공데이터를 업로드하면 **5대 품질 지표**(완전성·유효성·일관성·이상치·중복성)로 자동 진단하여 **0~100점 점수**와 **AI-Ready 등급**(S/A/B/C/F)을 산출하고, 결과를 **MySQL에 영구 저장**하는 웹 기반 데이터 품질 스코어카드 시스템.

### 1.2 핵심 가치

| 항목 | 내용 |
|---|---|
| **자동화** | 업로드만 하면 5대 지표 자동 진단 |
| **객관성** | 정량화된 점수 + 표준 등급 |
| **추적성** | 모든 진단 이력이 DB에 저장되어 시계열 분석 가능 |
| **확장성** | FastAPI 기반 REST 구조로 향후 다양한 클라이언트 연동 가능 |

### 1.3 주요 화면 (개요)

- **진단 실행 화면**: CSV 업로드 → 5대 지표 점수 → 종합 점수 → AI 요약 → 시각화
- **이력 조회 화면**: MySQL 저장된 모든 진단 결과 시계열 추이

## 2. 개발 배경 및 목적

### 2.1 배경

AI 모델의 성능은 학습 데이터의 품질에 크게 의존한다. 공공데이터포털 등에서 제공되는 대량의 데이터를 AI 학습에 활용하기 위해서는, 데이터의 결측·이상치·중복·형식 오류 등을 사전에 진단할 필요가 있다.

**문제점**:
- 기존에는 데이터 분석가가 수작업으로 품질을 검토 → 시간 소모, 일관성 부족
- 데이터셋마다 진단 기준이 달라 비교가 어려움
- 진단 결과를 영구 저장·관리하는 표준 시스템 부재

### 2.2 목적

1. **표준화된 5대 품질 지표**로 어떤 CSV든 동일 기준 평가
2. **AI 학습 가능 여부**를 등급(S~F)으로 즉시 판정
3. 진단 결과를 **DB에 영속화**하여 데이터셋 간 비교 및 시계열 추적
4. **누구나 사용 가능한 웹 인터페이스** 제공

### 2.3 기대 효과

- 데이터 사전 검토 시간 단축 (수작업 대비 수십 배)
- 데이터셋 품질 의사결정의 객관성 확보
- AI 학습용 데이터 선별 기준 마련

### 4.3 설계 원칙

- **관심사 분리(SoC)**: 화면·로직·데이터 각자 독립 모듈
- **단방향 의존성**: Presentation → API → Service → Persistence (역방향 의존 없음)

- **REST 표준 준수**: Swagger 자동 문서화(/docs)

## 5. 5대 품질 지표 설계

플로우차트 STEP 3 기반 5개 차원의 품질을 정량 측정한다.

### 5.1 지표 정의

| 지표 | 영문명 | 가중치 | 정의 |
|---|---|:---:|---|
| **완전성** | Completeness | 30% | 결측치(빈 셀)가 적은가? |
| **유효성** | Validity | 25% | 데이터 타입과 범위가 올바른가? |
| **일관성** | Consistency | 20% | 형식·표기가 통일되어 있는가? |
| **이상치** | Accuracy | 15% | 통계적 이상값이 적은가? |
| **중복성** | Uniqueness | 10% | 중복 행이 없는가? |

### 5.2 측정 알고리즘

#### ① 완전성 (Completeness)
```
점수 = (1 - 결측 셀 / 전체 셀) × 100
```
- `pandas.DataFrame.isnull().sum()` 기반
- 컬럼별·전체 결측률 동시 산출

#### ② 유효성 (Validity)
- 문자열 컬럼에서 숫자/날짜로 변환 가능한 비율이 70% 이상이면 해당 타입으로 간주
- 변환 실패 셀 → 무효(invalid) 처리
- 수치형 컬럼의 `inf`, `-inf`도 무효로 카운트
```
점수 = (1 - 무효 셀 / 전체 셀) × 100
```

#### ③ 일관성 (Consistency)
다음 3가지 패턴을 검사:
- **앞뒤 공백**: `' Alice'`, `'Alice '` 같은 공백 셀
- **대소문자 변형**: `'Alice'`, `'alice'`, `'ALICE'` 같은 표기 혼용
- **구분자 혼용**: `2024-01-01`, `2024/01/01` 동시 존재
```
점수 = (1 - 비일관 셀 / 전체 셀) × 100
```

#### ④ 이상치 (Accuracy) —  다수결 앙상블

**3개 알고리즘을 동시 적용 → 2개 이상에서 이상치로 판정한 셀만 최종 이상치**

| 알고리즘 | 판정 기준 |
|---|---|
| **IQR** | `Q1 - 1.5×IQR` 미만 또는 `Q3 + 1.5×IQR` 초과 |
| **Z-Score** | `|Z| ≥ 3` (평균에서 3 표준편차 이상 떨어짐) |
| **Isolation Forest** | 머신러닝 기반 격리 점수 (contamination 5%) |

```
점수 = (1 - 앙상블 이상치 / 수치형 셀) × 100
```

**다수결의 이점**: 각 알고리즘의 약점(IQR=대칭 분포 가정, Z-Score=정규분포 가정, IForest=무작위성)을 상호 보완.

#### ⑤ 중복성 (Uniqueness)
```
점수 = (1 - 중복 행 / 전체 행) × 100
```
- `pandas.DataFrame.duplicated()` 기반

## 6. 점수 산출 및 등급 판정

### 6.1 종합 점수 산식

```
종합점수 = 완전성 × W₁ + 유효성 × W₂ + 일관성 × W₃ + 이상치 × W₄ + 중복성 × W₅
```

- 기본 가중치: W₁=0.30, W₂=0.25, W₃=0.20, W₄=0.15, W₅=0.10 (합=1.0)
- 사용자가 사이드바 슬라이더로 조절 가능
- 입력값은 서버에서 합 1.0이 되도록 **자동 정규화**

### 6.2 AI-Ready 등급 체계

| 등급 | 점수 범위 | 의미 |
|:---:|:---:|---|
| **S** | 97점 이상 | 즉시 학습 가능 — 매우 우수 |
| **A** | 90 ~ 97점 | Class A 기준 — 우수 |
| **B** | 80 ~ 90점 | 경미한 보완 필요 |
| **C** | 70 ~ 80점 | 전처리 필요 |
| **F** | 70점 미만 | 학습 부적합 |

### 6.3 컬럼별 점수

각 컬럼에 대해 중복성을 제외한 4개 지표(완전성·유효성·일관성·이상치)의 가중평균으로 컬럼별 점수 산출 → Drill-down 분석에 활용.

## 7. 데이터베이스 설계

### 7.1 ER 다이어그램 (단일 테이블)

```
┌─────────────────────────────────────────────┐
│           diagnosis_history                  │
├─────────────────────────────────────────────┤
│ PK  id                  INT (AUTO_INCREMENT)│
│     filename            VARCHAR(255)         │
│     checked_at          DATETIME  [INDEX]    │
│     total_rows          BIGINT               │
│     missing_count       BIGINT               │
│     duplicate_count     BIGINT               │
│     outlier_count       BIGINT               │
│ ─── 5대 지표 점수 ──────────────────────────│
│     completeness_score  FLOAT                │
│     validity_score      FLOAT                │
│     consistency_score   FLOAT                │
│     accuracy_score      FLOAT                │
│     uniqueness_score    FLOAT                │
│ ─── 종합 ──────────────────────────────────│
│     quality_score       FLOAT                │
│     grade               VARCHAR(2) [INDEX]   │
└─────────────────────────────────────────────┘
```

### 7.2 스키마 상세

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | INT PK | 자동 증가 진단 ID |
| `filename` | VARCHAR(255) | 업로드 파일명 |
| `checked_at` | DATETIME | 진단 일시 (인덱스) |
| `total_rows` | BIGINT | 전체 행 수 |
| `missing_count` | BIGINT | 결측치 개수 |
| `duplicate_count` | BIGINT | 중복 행 개수 |
| `outlier_count` | BIGINT | 이상치 개수 (앙상블) |
| `completeness_score` | FLOAT | 완전성 점수 |
| `validity_score` | FLOAT | 유효성 점수 |
| `consistency_score` | FLOAT | 일관성 점수 |
| `accuracy_score` | FLOAT | 이상치 점수 |
| `uniqueness_score` | FLOAT | 중복성 점수 |
| `quality_score` | FLOAT | 종합 점수 |
| `grade` | VARCHAR(2) | 등급 (S/A/B/C/F, 인덱스) |

### 7.3 인덱스 설계

- `idx_checked_at`: 시계열 조회 최적화
- `idx_grade`: 등급별 필터링 최적화

### 7.4 ORM 매핑

SQLAlchemy 2.0 declarative 방식으로 `models.py`에 정의. 세션은 요청 단위 발급/종료.

|  **컬럼 Drill-down** | 컬럼 선택 → 5지표 상세 분석 |
|  **데이터 이슈** | 유효성 이슈, 종합 요약 테이블 |

#### 메뉴 2: 진단 이력 (DB) — 3개 탭

| 탭 | 내용 |
|---|---|
|  **이력 요약** | 저장 건수, 평균/최고/최저 점수, 시계열 트렌드 차트 |
|  **전체 목록** | MySQL의 모든 진단 기록 테이블 |
|  **이력 관리** | ID 기반 삭제 |

### 9.2 디자인 시스템

- **테마**: 다크 모드 (`#0E1117` 배경, `#F3F4F6` 텍스트)
- **포인트 컬러**: 청록 그라데이션 (`#00D4FF` → `#C77DFF`)
- **등급 컬러 코딩**: S=보라, A=초록, B=파랑, C=노랑, F=빨강
- **반응형**: CSS `clamp()` 활용한 폰트 크기 자동 조정
- **인터랙티브 차트**: Plotly (호버 정보, 줌, 다운로드 지원)

### 9.3 사용자 흐름 (User Flow)

```
[시작] → CSV 업로드 → 가중치 조절(선택) → 자동 진단
   ↓
[결과 화면]
   ├─ KPI 5종 확인
   ├─ 5대 지표 레이더 차트 확인
   ├─ AI 요약 텍스트 확인
   ├─ 컬럼 Drill-down (선택)
   └─ 데이터 이슈 확인
   ↓
[MySQL 자동 저장] → "진단 이력 (DB)" 메뉴에서 누적 추이 확인
```
